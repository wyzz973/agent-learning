# 雾岛图书馆：开馆行动

你是一名从零起步的新人工程师，要亲手造出图书馆助手**阿灯**。馆长**林禾**逐次提出委托：回答馆务问题、办理研究请求、保留进度与方法、提供可调用服务，以及维护助手自己的代码组件。课程不预设编程或 agent 经验；每项新写法都从当前任务需要解决的问题讲起。

**始终从[根入口](../README.md)的当前 Notebook 开始。** 任务故事、必需素材、Python 写法、框架接口、教师示范、本人代码和验收在同一页。这个目录保存课程中逐渐积累的作品，不是额外的学习入口。

## 开馆意味着什么

访客得到的答复能找到依据；林禾提交研究委托后能查看进度、审核结果；中断的任务能恢复；常用研究方法能被正确使用；另一个客户端能调用阿灯；组件出现缺陷时，有经过隔离测试的修复候选。

| 区域 | 阿灯获得的实际能力 | 能看见的作品 |
|---|---|---|
| M01 门厅 | 接收输入，根据提供的资料回答 | 第一段本人程序与有来源的馆规答复 |
| M02 问询台 | 通过工具查资料，利用错误反馈 | 真实资料读取与工具调用记录 |
| M03 委托台 | 根据问题和证据控制处理流程 | 可观察的状态、分支与反馈循环 |
| M04 值班室 | 保留进度、记忆与人工审核结果 | 可恢复的研究委托 |
| M05 研究阅览室 | 明确范围，查找公开技术证据 | 为数字图书馆建设提供依据的研究报告 |
| M06 出版与服务台 | 检查质量，接受独立客户端调用 | 可使用的研究服务与评估记录 |
| M07 方法与工具交换站 | 通过 MCP 共享能力，按需使用 Skills | 可复用工具与实际生效的方法包 |
| M08 维修间 | 修改允许的代码并在隔离环境验证 | 助手组件的补丁、测试与回归结果 |

这些是任务目标，不表示能力已经实现。奖励是实际产物和有证据的新能力，不设虚拟经验值，也不因跑过示范自动认定掌握。

## 世界、资料与作品

`world/` 承担虚构馆务素材：馆规、馆藏、角色委托与需求。当前 Notebook 必须呈现完成任务需要的部分，不让学习者自己寻找缺失资料。

M05 起的技术研究加入真实公开证据，明确原文位置、获取时间和支持的主张。虚构馆务与真实技术资料分别标识；公开文档不能把故事中的需求变成真实调查结果。陌生主题只作明确标注的迁移实验。

作品逐步形成委托单、来源资料、证据摘录、答复或研究报告、运行记录。需要哪种结构，就在当前页解释和定义哪一种，不要求入门先理解全部类型。后续任务实际使用本课程本人产物，展示输入来源及去向，不能只打印产物后换用另一份演示数据。

## 怎样知道自己学会了

每项委托经过“尝试 → 发现缺口 → 学习机制 → 本人实现 → 验证 → 暂停机制做对照 → 换输入迁移”。三种进度分别记录：

- **机器可运行**：真实调用与检查产生了可查看的结果。
- **本人能解释**：能指出自己的输入、代码、行为变化和验证依据。
- **迁移成功**：换一个合理输入或条件，仍能完成并说明边界。

教师运行只属于教材验证，不代替以上本人证据。一个任务可以分多次完成；停下时留下当前单元格、可运行部分、卡点和下一动作。
