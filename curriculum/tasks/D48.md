# D48 · w13 · 加入规则评分与人工判读

## 今天要做什么

规则核对文件/来源/错误处理；人工看两条；对比 LLM judge 的局限。

产物/编辑位置：`ex1_grading.py（开周创建）`。该周代码由导师在开周时按此契约准备，尚未生成；这里已经规定学习动作与验收，不把它说成可运行。

## 为什么这样做

单个通过率容易掩盖失败类型。

## 核心思想

可机械验证的用规则，主观质量用明确量表。

## 能学到什么

Python：数据集、参数化测试、时间统计、JSONL。Agent 能力：加入规则评分与人工判读。只学习本任务用到的写法；术语到[词典](../../GLOSSARY.md)，接口到[API 手册](../../API_GUIDE.md)按词查。

## 前置条件

完成 [D47](D47.md) 的必要验收；不懂就接着原任务练。

## 60 分钟步骤

1. **5 分钟**：不看答案说出上次任务的输入、输出和一个失败情况。
2. **10 分钟**：读本课所需热身/示范，先预测输出，再运行；让导师分清语法与 API。
3. **30 分钟**：规则核对文件/来源/错误处理；人工看两条；对比 LLM judge 的局限。每次只改一小处、运行一次。
4. **10 分钟**：按下面验收核对结果，用自己的话说明“哪个数据交给了谁”。
5. **5 分钟**：在学习状态留下实际证据、卡点与下一步；问答由模型逐字记录。

开始/检查命令（仓库根目录）：

```sh
uv run python scripts/learn.py --task D48
```

这条命令先显示任务契约；该周教材生成后，导师要在当周 README 给出并实测具体运行与测试命令。

## 验收标准

- [ ] 评分依据可复核；不把 judge 判断当唯一真值。
- [ ] 本人能解释核心思想，指出一个容易写错的地方。
- [ ] 状态记录使用实际结果，未完成/未运行明确标注。迁移或重写需要本人动手。

下次学习开头回忆本课，不以提前看完下一课代替本课验收。

## 卡住怎么办

先定位卡在数据形状、语法、调用还是返回；展示最小输入、预期输出和第一条错误。让导师先给方向或相似例子，保留自己的实现机会。60 分钟到仍未完成就续做此任务，不叠加下一课。
