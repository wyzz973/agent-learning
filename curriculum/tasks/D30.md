# D30 · w09 · 长任务交接演练

## 今天要做什么

另一终端/模型接手未完成任务；先读状态再恢复；核对结果。

产物/编辑位置：`test_w09.py（开周创建）`。该周代码由导师在开周时按此契约准备，尚未生成；这里已经规定学习动作与验收，不把它说成可运行。

## 为什么这样做

把 harness 连续性变成应用自身能力。

## 核心思想

持久状态、进度记录和验证工件一起支撑恢复。

## 能学到什么

Python：JSON 文件、上下文管理器、SQLite 基本读写。Agent 能力：长任务交接演练。只学习本任务用到的写法；术语到[词典](../../GLOSSARY.md)，接口到[API 手册](../../API_GUIDE.md)按词查。

## 前置条件

完成 [D29](D29.md) 的必要验收；不懂就接着原任务练。

## 60 分钟步骤

1. **5 分钟**：不看答案说出上次任务的输入、输出和一个失败情况。
2. **10 分钟**：读本课所需热身/示范，先预测输出，再运行；让导师分清语法与 API。
3. **30 分钟**：另一终端/模型接手未完成任务；先读状态再恢复；核对结果。每次只改一小处、运行一次。
4. **10 分钟**：按下面验收核对结果，用自己的话说明“哪个数据交给了谁”。
5. **5 分钟**：在学习状态留下实际证据、卡点与下一步；问答由模型逐字记录。

开始/检查命令（仓库根目录）：

```sh
uv run python scripts/learn.py --task D30
```

这条命令先显示任务契约；该周教材生成后，导师要在当周 README 给出并实测具体运行与测试命令。

## 验收标准

- [ ] 无需口头补充即可定位下一步；未知内容不会被补成已完成。
- [ ] 本人能解释核心思想，指出一个容易写错的地方。
- [ ] 状态记录使用实际结果，未完成/未运行明确标注。迁移或重写需要本人动手。

这是本周复盘课：关闭原实现，换一组输入重写本周最关键的一个小函数；在 notes/weekly 的对应文件记录查过的资料和真实卡点。

## 卡住怎么办

先定位卡在数据形状、语法、调用还是返回；展示最小输入、预期输出和第一条错误。让导师先给方向或相似例子，保留自己的实现机会。60 分钟到仍未完成就续做此任务，不叠加下一课。
