## 卡在哪，怎么通的

**1. `with_retry` 返回了 `None`，报错却在三层之外**

`for` 循环跑完忘了 `raise RetryExhausted`，函数走到末尾，Python 悄悄返回 `None`。
不报错，一路传到 `main` 里 `len(result)` 才炸成 `TypeError: object of type 'NoneType' has no len()`。

排错路线：`len(None)` 炸 → `result` 是 `None` → 但 `gather(return_exceptions=True)` 只产出「返回值」或「异常对象」→ 所以是某个任务**正常返回**了 `None` → 那个任务是 `with_retry` → 看它哪条路径没 return → 循环之后是空的。

**报错的地方通常不是出错的地方。** 从报错点往回追数据是从哪来的。

**2. `httpx.ConnectError` 不是内置的 `ConnectionError`**

`retry_on` 默认写的是内置异常，结果 httpx 的连接失败一次都没重试就抛出去了。
第三方库有自己的异常体系，不继承内置的。要显式传 `retry_on=(httpx.ConnectError, httpx.TimeoutException)`。

**3. 给 pydantic 传 `None` ≠ 不传**

`os.environ.get(name)` 取不到时返回 `None`，于是 `Settings(llm_timeout_seconds=None)`，
默认值 `60.0` 被顶掉，pydantic 报 `Input should be a valid number`。
不传这个键才会走默认值。修法是字典推导式加过滤：`if name.upper() in os.environ`。

**4. `.splitlines()` 切开了但忘了取 `[0]`**

`description` 成了整个 docstring 切出来的列表。同类的还有 `collect_tools` 收集了函数对象本身，
而不是函数身上挂的 `__tool__` 字典。

两次都是**做对了最难的一步，停在最后一个取值动作上**。
以后写完对着 docstring 的 `Returns:` 念一遍：我 return 的东西和这里写的是同一个吗？

**5. 错误信息要带上出错的那个值**

`resolve_model` 抛了 `ValueError` 但只说「格式不对」，没说是哪个值不对。
`load_settings` 让 pydantic 报错，它说的是字段名 `default_model`，而人需要知道去 `.env` 里改 `DEFAULT_MODEL` 那一行。
**错误信息要直接指向解决办法，不只是指出哪里不对。**

**6. lint 抓到的三个**

- `F811`：局部变量 `fields` 遮蔽了顶部导入的 `Field`
- `B904`：`except` 里抛新异常要写 `raise ... from error` 或 `from None`
- `B007`：只用值不用键时该用 `.values()` 而不是 `.items()`
