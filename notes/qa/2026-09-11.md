    middleware = [ToolErrorMiddleware(on_error= lambda error, )]  这个我不会写  不知道怎么写lambda

<a>
第 157 行报的就是你那行没写完的 lambda：`Expected ':', found ')'`，意思是它读到 `)` 的时候还在等冒号。那是你正在写的代码，我没动。

**lambda 就是一行写完、没有名字的函数。**下面两种写法效果完全一样：

```python
def describe(error, request):
    return f"工具执行失败：{error}"


lambda error, request: f"工具执行失败：{error}"
```

逐个看 lambda 那一行：
- `lambda`：表示这里要定义一个函数
- `error, request`：参数，和 `def` 括号里一样，用逗号隔开
- 冒号 `:` 后面：返回值，会自动返回，不用写 `return`

你写到 `lambda error, ` 就停了，缺第二个参数 `request`，也缺冒号和后面的返回值。

这个 lambda 在 docstring 的提示里已经写全了，可以直接抄：

```python
lambda error, request: f"工具执行失败：{error}"
```

`request` 在函数里用不到，但必须写上。`ToolErrorMiddleware` 调用你的函数时总是传两个值进来，少写一个参数就会报错。

补完这一行后，函数最后还要返回 agent。可以照着同一个文件里我写好的 `build_agent`：它是 `create_agent(model=..., tools=..., system_prompt=...)`，你这里把 `system_prompt=...` 换成 `middleware=middleware`。

写完跑这条测试：

**21:48 · Week 03 · pytest 命令各参数的意思**

<q>
uv run pytest weeks/w03-langchain-core -q -k  这个命令的参数是什么意思？
</q>

<a>
从左到右拆开：

| 部分 | 意思 |
|---|---|
| `uv run` | 用项目自己的虚拟环境（`.venv`）来执行后面的命令，不用先手动激活环境 |
| `pytest` | 测试工具。它会找 `test_` 开头的文件，再跑里面 `test_` 开头的函数 |
| `weeks/w03-langchain-core` | 只在这个目录里找测试。不写的话，会跑 `pyproject.toml` 里 `testpaths` 配置的全部目录 |
| `-q` | quiet，输出精简：每条测试一个点，最后给汇总 |
| `-k "..."` | 按名字筛选，只跑名字里带这个关键词的测试 |

`-k` 后面可以用 `or` / `and` / `not` 组合：

```bash
-k resilient                      # 名字含 resilient 的
-k "resilient or escape"          # 含 resilient 或含 escape 的
-k "TestTools and not dangerous"  # TestTools 类里，除了名字含 dangerous 的
```

它匹配的名字包括类名，所以 `-k TestTools` 能一次选中整个类。

另外两个常用的：

```bash
-v   # verbose，每条测试一行，显示名字和 PASSED/FAILED，比 -q 详细
-x   # 遇到第一条失败就停下，一堆红的时候先专心修第一个
```

**22:25 · Week 03 · f-string 大括号分错导致 unhashable type: 'dict'**

<q>

执行轨迹：

<a>
f-string 的大括号分错了：

```python
f"ai->{call['name']({call['args']})}"  # 你写的：一对大括号包住了全部
f"ai -> {call['name']}({call['args']})"  # 要的：两对大括号，( ) 在外面
```

f-string 的规则：**`{}` 里面是 Python 代码，外面是原样输出的文字。**你想打印出来的 `(` 和 `)` 是文字，要放在大括号外面。

正确写法逐段看：

- `ai -> `：文字
- `{call['name']}`：代码，结果是 `get_weather`
- `(`：文字
- `{call['args']}`：代码，结果是 `{'city': '上海'}`
- `)`：文字

你的写法把整段 `call['name']({call['args']})` 放进了一对大括号里，Python 就把它当代码执行，出了两个问题：

- `call['name'](...)` 把字符串 `'get_weather'` 当成函数去调用
- 代码里的 `{call['args']}` 是集合（set）的写法，意思是"造一个装着这个字典的集合"。字典不能放进集合，所以报 `unhashable type: 'dict'`

报错指向第二个，是因为 Python 先执行到了那里。

我上一条给的写法就是两对大括号，抄的时候把两段并成了一段。

## 1. `match` 要看的是 role，不是所有值

```python
match m.values():     # ✗
```

它永远不会等于 `"system"`，所以每一条都会掉进 `case other`，直接抛错。你要比的是 role 那一个值。

## 2. 只有 system 分支 append 了

## 1. `json.load` 要写成 `json.loads`

两条测试报的是：


`json.load` 读的是**文件**，它会去调用 `.read()`；`json.loads` 解析的是**字符串**，名字里那个 s 就是 string。你手上的 `c["arguments"]` 是字符串，所以要用 `loads`。记法：带 s 的吃字符串。

```
TypeError: 'NoneType' object is not subscriptable
```

函数没写 return，默认返回 `None`，测试拿到 `None` 再去取第 0 个元素，就报这个错。在循环结束后、和 `for` 对齐的位置加一行 `return messages`。

这里又变回直接取 content 了。w02 里模型只调工具时 content 是 `None`，而 `AIMessage` 不接受 `None`。现在还没报错，是因为前面的 `json.load` 先出错了；把 json 改好之后，这里会接着报 `ValidationError`。改回 `m.get("content") or ""`。
