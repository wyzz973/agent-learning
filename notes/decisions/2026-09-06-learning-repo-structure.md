# Decision: 学习仓库按"练习/沉淀"二分，AI 只当陪练不当代笔

Status: implemented

## Problem

12 周的 agent 学习要用一个仓库承载，而学习仓库和产品仓库的成功标准不同：产品仓库要代码能跑、能维护；学习仓库要**人的能力真的长出来**。这带来两个具体风险。

一是用 Claude Code 学编程有个天然矛盾：AI 写得又快又好，我全程看着它写，一周后什么都不会。每天只有 1 小时的预算下，这个风险特别高——用 AI 写完显得"进度很快"，但进度是假的。

二是代码组织。每周从零开一个新目录，学的东西不累积；全塞进一个演进的项目，又会为了保持整洁而不断回改旧代码，把"第 3 周我当时的真实水平"这个信息抹掉。

## Decision

**目录按 `weeks/`（一次性练习）和 `src/agentlab/`（跨周沉淀）二分。** 练习允许粗糙，完成即冻结，不回改；沉淀必须有类型、测试、docstring，`mypy --strict` 通过。代码从练习提升到沉淀要写一条决策记录，标准是"下一周还会再用"。

**AGENTS.md 的第一章规定 AI 的教学行为，不是代码风格。** 核心一条：AI 不写 `weeks/` 下的主练习文件，只做 review、解释、debug、写测试和工具。配套的还有先问再讲、深度匹配问题、不确定就搜并给 URL、反对过早复杂化。

**AI 自动把每次有学习内容的问答逐字追加到 `notes/qa/YYYY-MM-DD.md`，XML 标签包裹。** 学习过程中的问答是最有价值的资产，平时它散落在聊天记录里丢掉了。

**每周 README 走 Build It → Use It → Ship It 三段**，其中 Use It 必须包含手写版与框架版的对比表。

**所有可机械检查的规则接进 `./check.sh`。** 结构、死链、密钥卫生由 `scripts/check_structure.py` 检查。

## Alternatives rejected

**每周独立目录，不设 `src/`。** 最简单，但学到第 8 周时前 7 周的代码全是死的，"哪些代码值得留下"这个判断也永远练不到。二分带来的额外负担只是一条决策记录。

**单一演进项目，每周重构。** 更接近真实工程，但会诱导我不断回改旧代码。冻结旧周代码是有意的：它是能力增长的存档，回头看第 2 周的裸 agent 才能感受到差距。

**照搬 dsh 的完整规范**（分层 AGENTS.md、词数预算、文档 tier taxonomy、lifecycle/class 路径编码的决策记录、多个 verify 脚本）。那套是为几十个包的团队项目设计的，单人学习仓库套上去，每次改动的仪式感会挤占本就只有 1 小时的学习时间。保留的是它真正跨规模成立的部分：AGENTS.md 作为唯一常驻入口、一个事实一个家、决策记录写"为什么和放弃了什么"、文档写现状不写变更史、可机械检查的规则必须接进能跑的 gate。

**只写 README 加 commit 规范，靠自觉。** 没有 gate 的规范三周内必然废弃。`check.sh` 的存在本身就是规范能活下来的原因。

**让 AI 全程代写，我只读代码。** 表面进度最快。放弃它的理由就是这个仓库存在的理由——12 周后要的是我能独立写出来，不是仓库里有多少行能跑的代码。

## Verification

`./check.sh` 在空仓库状态下正确报出缺失项（周目录、死链、密钥卫生三类），退出码 1。规则不是写在文档里靠自觉，而是每次提交前被执行。

真正的验证在第 2 周末：如果我能不看资料手写出 agent loop，这套规范就起作用了；如果不能，先怀疑"AI 不写主练习文件"这条有没有被真的执行。
