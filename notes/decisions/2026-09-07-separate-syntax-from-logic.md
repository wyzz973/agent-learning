# Decision: 语法与逻辑分开学，每周前置 00_warmup.py

Status: superseded — 见 [基础写作与小工具](2026-09-11-python-first-agent-tools.md)

## Problem

三段坡道（[上一条决策](2026-09-06-scaffolded-exercise-gradient.md)）解决了"从空白起步"的问题，w01 的完成度证明它有效：ex1 两段独立写对，`with_retry` 的 try/except、`asyncio.timeout`、指数退避也都写对了。

但主观感受是"会卡死在语法上，一行代码都不会写"。**客观完成度和主观体验出现了大幅落差**，而落差本身就是要解决的问题——痛苦的过程撑不过 12 周。

根因是每个练习同时引入太多没见过的语法。`with_retry` 一个函数里就有：`Callable[[], Awaitable[T]]`、强制关键字参数的 `*`、`tuple[type[Exception], ...]`、`async with asyncio.timeout()`、`except X as e`、自定义异常类、指数运算。对只掌握基础语法的人，这是七个新东西一起上。

**他不是在解一道题，是在同时解两道**：这段逻辑该怎么组织，以及这个语法怎么写。任一道卡住，另一道也跟着停。

## Decision

**每周目录必须有 `00_warmup.py`，做练习前先跑。** 本周会用到的每个新语法一个最小可运行例子，带 print 输出，只读只跑不用写，约 15 分钟。`scripts/check_structure.py` 检查它存在。

**练习里不许出现 warmup 没覆盖过的新语法。** 这是硬约束，写练习时倒推 warmup 该覆盖什么。

**新增 [SYNTAX_CARDS.md](../../SYNTAX_CARDS.md)，按「我想做什么」组织而不是按语法分类。** 写代码时对着查。学习者知道自己要干什么（"把列表里的协程一起跑"），不知道对应的写法叫什么名字（"gather 加星号展开"），所以按语法名组织的资料查不到。

**逻辑正确优先于写法地道。** 用已掌握的语法笨办法写对就算过，地道写法留到每周 README 的 Use It 那节再对比。不为了"应该用推导式"去改已经能跑的代码。

## Alternatives rejected

**停下来专门补两周 Python。** 在 [仓库结构决策](2026-09-06-learning-repo-structure.md) 里已经拒绝过一次，现在依然拒绝，但理由要更新：不只是"脱离场景学完就忘"，更是**证据不支持**——他并非不会写代码，而是在同时处理两类新信息时超载。隔离变量比补课更对症，而且不花掉两周。

**削减练习用到的语法，只用基础写法。** 那样 `with_retry` 就退化成同步阻塞的循环，`@tool` 也没法写。这些语法不是炫技，是 agent 开发的日常构件，绕不过去。

**把语法解释直接写进练习文件的注释。** 已经在做，但不够：注释是"读到那一行才看到"，而卡住往往发生在写第一个字之前。warmup 是**先看一遍全貌**，性质不同。而且注释写多了会淹没代码本身。

**遇到语法问题就问 AI。** 他一直这么做，也确实能推进，但每次都要中断心流等一轮问答，而且答案散落在对话里不成体系。warmup 和速查卡是可反复查阅的、留在仓库里的资产。

## Verification

`uv run python weeks/w01-python-foundations/00_warmup.py` 跑通十个小节，其中 late binding 一节直接打印出 `[2, 2, 2]` 与 `[0, 1, 2]` 的对比，Semaphore 一节打印出并发数从未超过 2。

`scripts/check_structure.py` 新增 `00_warmup.py` 存在性检查，缺失时周目录检查报红。

真正的验证在 w02：如果学习者在 ex 里遇到新语法时会主动回查 warmup 或速查卡，而不是卡住等提问，这个设计就成立。如果仍然卡死，下一步是把练习拆到更小的粒度——一个练习只引入一个新语法。
