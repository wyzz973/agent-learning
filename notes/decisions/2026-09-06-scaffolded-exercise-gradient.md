# Decision: 练习文件按三段坡道写，AI 提供示范和骨架

Status: implemented

## Problem

第一版 w01 的五个练习文件，函数体全是 `raise NotImplementedError`，只留签名和 docstring。设计依据是 [仓库结构决策](2026-09-06-learning-repo-structure.md) 里那条"AI 不写 `weeks/` 下的主练习文件"。

实际拿到手后的反馈是"不知道怎么写代码，我的代码基础很薄弱，一直都是在 vibe coding"。

这不是态度问题，是台阶高度设错了。**vibe coding 的经验是"描述需求—验收产出"，不包含"从空白文件开始组装代码"这一步。** 直接给一个空壳，等于要求一个从没独立写过代码的人凭空产出——他缺的不是意志，是一个眼前可参照的例子。

同时 25 个测试全红，对新手是纯负反馈，看不出任何进展。

## Decision

**每个练习文件写成三段坡道**，同一个文件内难度递增：

1. **示范** — 完整实现 + 逐行注释，标「已实现，先读懂」。读懂并运行，不动手写。
2. **填空** — 结构写好，关键一到三行留 `TODO` 并写明思路和提示。
3. **独立** — 只有签名和分步思路，照前两段的模式自己写。

**AI 写第 1、2 段，第 3 段和 TODO 的答案永远由学习者写。** 原规则的意图（能力必须长在人身上）不变，变的是台阶高度。

**示范段让一部分测试开局就绿。** w01 由此从 25 红 2 绿变成 20 红 7 绿。开局有绿是有意的正反馈。

**每个练习文件顶部标注"练到的 Python"，汇总进 [PYTHON_TRACK.md](../../PYTHON_TRACK.md)。** 学习者同时要提升 Python，但每天只有 1 小时，开第二条学习线不现实——让 Python 训练寄生在 agent 练习里。

**每周 README 写明"不知道从哪下手"的具体动作**：跑测试看清单、只读第 1 段、改参数观察输出、`-k` 单跑一条测试、traceback 从下往上读。

## Alternatives rejected

**降低练习难度或减少数量。** 治标。难度不是问题，**从空白起步**才是问题——有了可参照的示范，同样难度反而能推进。而且削薄第一周会让后面每周都更吃力。

**AI 全写，学习者只读。** 回到 vibe coding，这个仓库就没有存在意义了。

**给完整答案放在单独的 solutions/ 目录，允许卡住时查看。** 试过这个思路的人都知道结局：卡住的定义会不断放宽，最后变成先看答案再写。坡道把"参照"内建在同一个文件里，参照的是**结构相似但不同的函数**，抄不过来，只能理解后改写。

**先花两周专门补 Python 再开始 agent。** 每天 1 小时的预算下，两周纯语法练习会先耗掉动力，而且脱离场景的语法学完就忘。让 Python 寄生在有真实用途的练习里，学完立刻用上。

## Verification

w01 改造后 `uv run pytest weeks/w01-python-foundations -q` 为 20 failed / 7 passed，`./check.sh --wip` 全绿。

真正的验证在本周结束：如果第 3 段（`run_concurrent_limited`、`collect_tools`、`resolve_model`）能独立写出来，坡道高度就是对的。如果第 3 段仍然卡死，下周把第 2 段的 TODO 留得更细，而不是直接给答案。
