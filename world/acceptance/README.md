# 林禾的开馆验收问题纸

development.json为12个开发案例，holdout.json为8个留出案例。馆务都是雾岛虚构资料，技术研究使用真实官方原文。只把request交给本人runtime；expected_status与checks交给评分器，不能进入被测模型输入。

expected_status是本关约定的目标状态，不是已经运行的结果。保存实际输出、缺口、失败、预算、出处和版本。留出前锁定本人组件、prompt与uv.lock，使用后若再调试候选，应明确称下一轮开发/回归，不能继续冒称独立留出。

完整20案对应M10-T02的上限；可按任务类型分批完成，每批分别保存。规则检查和语义审计分开，取消、恢复、隔离维修等实验需额外实际执行证据，不能只靠这张输入表证明。

涉及撤回、冲突、取消和恢复的案例，先在本课匿名环境准备对应实际状态再运行：撤回案要有数据库回读，冲突案要提供两份不同版本，取消案从实际任务启动后用取消API/按钮停止，恢复案记录两次进程与同一任务ID。自然语言说“取消/恢复”本身不会制造这些事实。若任务在取消请求前已经完成，应保存实际时序并补一个仍在运行的任务，不伪造cancelled。模型允许波动，评分检查行为与支持关系，不要求逐字复现。
