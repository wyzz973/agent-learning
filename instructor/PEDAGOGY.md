# 雾岛图书馆：开馆行动的教学依据

核查日期：2026-09-13。课程视作全新项目，不预设 Python、框架或既往练习经历。学习者建设一位图书馆助手，帮助重新开馆：读懂馆务资料、回答读者问题、寻找出处、保留任务、核查报告。情景提供做事的理由，学习成果是本人能解释和实现的能力。

## 每次委托怎样成为一份 Notebook

开头用简短委托说明“谁遇到了什么困难、怎样才算解决”。例如，接待台需要依据借阅规则答复读者，助手却没有拿到规则。随后展示目标产物、解释信息如何进入模型，并在同一本中提供必要语法、示范、本人实现和验收。结尾回到委托：读者现在能得到什么，哪里仍需核查。

每次通关留下真实产物，例如带出处的答复、可调用的检索工具、恢复后的任务或审核记录。新增代码接入同一个图书馆助手；不以多建一个文件或多打印一段话充当能力升级。

## 1. 先建立完整示例，再逐步撤去帮助

新概念第一次出现，先给完整问题、关键步骤和结果，解释每一步为什么需要。随后让本人完成缺少的关键步骤，最后独立处理同类委托。撤去的是逐步指导，输入输出契约仍清楚；不能一开始只留空函数，也不能始终只做简单填空。

例如先展示怎样把一条馆规放进消息，再让本人决定哪些资料应进入请求，最后独立完成另一条馆规的答复。新语法在使用处先解释，不把环境排障和陌生写法同时压给学习者。[Renkl 等，2002](https://www.tandfonline.com/doi/abs/10.1080/00220970209599510)的示例渐隐实验主要支持近迁移，不能据此保证复杂 agent 开发能力。

## 2. 用主动提取和换题区分看懂与会用

运行之后先收起示范，让本人说出资料、消息、工具结果各流向哪里；间隔一次学习后，再尝试写出关键机制。迁移委托保持机制相同，换读者问题、资料或失败条件，避免只靠记住一个答案。

例如借阅规则查询成功后，换成开放时间查询；检验本人函数是否真正使用新资料。回忆困难时给局部提示，并记录帮助程度。[Butler，2010](https://pubmed.ncbi.nlm.nih.gov/20804289/)在文本学习实验中观察到提取练习对保留和推断迁移的帮助；应用到代码课程仍需本人表现验证。

## 3. 反馈说明目标差距和下一步

委托开始就写明可观察的完成条件。失败反馈指出具体数据或执行路径，例如“查到了馆规，但下一次模型请求里没有工具结果”，再让本人修正和重跑。成功时展示改动怎样解决了委托；分别记录程序通过、结果有依据和本人能解释。

测试返回红绿之外，还应给预期、实际与检查位置。教师不靠修改答案或弱化断言制造通关。[Wisniewski 等，2020](https://pmc.ncbi.nlm.nih.gov/articles/PMC6987456/)的元分析显示反馈效果存在明显差异，信息内容很重要；不能把任何反馈都视为有效教学。

## 4. 获得感来自胜任与有意义的选择

“解锁”对应可展示的能力：助手能读取证据、保留调查进度，或发现不被原文支持的结论。允许本人选择一个读者问题、比较两种实现、决定需要哪一级提示；核心学习目标保持明确，避免让零基础学习者先设计整套路线。

积分和徽章可以省略。结果展示应突出本人作出的决定及实际效果，而非赞美聪明或排名。[Ryan 等，2006](https://link.springer.com/article/10.1007/s11031-006-9051-8)发现游戏中的自主性、胜任感与参与体验相关；这不证明游戏包装会提高编程成绩，更不承诺让人上瘾。

## 5. 剧情帮助理解，不新增一套学习负担

固定地点、主要角色和助手，让委托本身带出技术需求。代码旁仍写真实术语：列表、消息、状态、检查点、MCP；不用“魔法水晶”等别名遮住含义。不引入货币、战斗数值或必须记忆的人物关系。剧情可以略读，关键条件、代码与结果必须完整可读。

[Harp 与 Mayer，1998](https://eric.ed.gov/?id=EJ576496)研究了有趣但无关的附加信息对学习的干扰。由此采用的设计约束是：删掉某段剧情后若完全不影响理解委托，它通常应缩短或移除；这不意味着所有故事都有害。

## 教师怎样检查一份任务

从零读一遍，确认无需外部教案就能知道做什么、为什么、怎么看结果。再确认本人负责一个实质机制，提示逐渐撤去，故障可以解释，新委托能够检验迁移。最后分开记录教师示范、本人成果和仍需帮助的部分。这些研究提供设计依据，学习者的实际理解与反馈决定教材是否需要调整。
