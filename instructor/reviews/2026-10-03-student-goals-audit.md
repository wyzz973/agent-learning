### 3.2 工作、个人项目、求职和研发分别达到什么程度

**用于工作：具备较好的应用开发基础。** 工具执行、权限、检索、异步服务、恢复、错误定位都是可迁移的能力。仍需要一项实际工作流程验证：输入来自谁、目前人工怎样处理、允许哪些动作、正确结果如何核对、节省多少时间、失败如何转交。虚构馆务有利于安全练习，但不能替代一次真实业务分析。

**用于自己的项目：方向合适，但要完成脱离教材变量的迁移。** 完成同域“换公告”可以证明函数使用了参数；独立处理另一类资料、另一个工具或另一种数据来源，才更接近自主开发。毕业作品仍应继续服务雾岛图书馆，例如新增资料更新提醒、咨询工单分类或政策版本比较；关键在需求和实现选择不再由教师逐层给定。

**用于求职：作品潜力大于当前职业训练。** 学生若真正完成这些机制，会有比单一聊天 demo 更好的项目素材。但当前没有系统的岗位能力映射、作品筛选、面试设计取舍题和完整作品集验收。不能把“学完课程”换算为“已经能求职”，也不能据此推断录用率。应能当场改一个需求、解释一次故障、证明一项结果对应自己的代码。

**用于应用研发：有方法起点，尚缺实验深度。** 消融、证据审计、框架对照与裁判偏差是良好基础；要进一步做到比较策略、构造数据、复现实验、估计可靠性和解释收益来源。

**用于模型或算法研究：不足以单独支持。** 本课程重点是调用模型和搭建系统。没有完整的模型原理、训练、Agentic RL 或优化方法实践。这不应成为零基础主线的硬门槛，但需要诚实区分“应用系统研发”与“模型算法研发”。

### 4.1 是否能称为市面上独一份

**不能依据当前证据这样宣传。** 公开材料已经表明，“从原理到应用”“中文综合课程”“研究系统”“MCP/记忆/评估”“毕业项目”都有其他课程覆盖。特别是中文教程已经涉及研究、训练和职业素材，因此不能以技术目录长来证明唯一。

雾岛更有辨识度的是几项设计的组合：一个持续发展的中文场景；每关原位讲解；学生亲写核心机制；模型、工具和状态证据可见；统一自由接待台；故障、许可、撤回、版本、恢复与交接贯穿后续作品。**这种组合有形成课程特色的潜力，但“独特的组合”与“市场上只有这一份”是两种判断。**

更稳妥的课程定位是：

> 面向零基础学习者，以雾岛图书馆的连续委托学习 Agent 应用开发，亲手实现关键机制，并用真实运行、故障对照和迁移作品证明能力。

要形成更难替代的优势，需要展示学生的独立作品、经验证的学习跳步修复、跨关能力保留和真实迁移结果。当前没有足够的学习者样本来评价完成率、学习收益或相对教学效果。

## 五 技术方向与先进性

“先进”至少包括接口仍受维护、工程问题贴近实际、方法选择有证据。单纯使用较新的包名，或者加入更多 agent，不足以证明先进。稳定而可解释的机制也不应因提出较早而被淘汰。

| 技术方向 | 当前课程情况 | 判断 |
|---|---|---|
| LangChain 与 LangGraph | 使用当前 1.x 路线，实际涉及 create_agent、middleware、StateGraph、消息和异步接口 | 合理的主线。官方也将 agent 描述为模型与工具反馈循环，并区分 harness 职责。[官方文档](https://docs.langchain.com/oss/python/langchain/agents) |
| 上下文与记忆 | 区分消息、检查点、长期记忆、压缩、经验、版本与撤回 | 符合实际工程关注点；进一步衡量哪些内容进入请求以及效果如何。[官方工程资料](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) |
| DeepAgents 与 Skills | 实际比较成熟 harness，展示文件、方法、记忆与显式规划 | 属于有用的当代工程路线；不能从一次对照宣称某框架更强。[DeepAgents 文档](https://docs.langchain.com/oss/python/deepagents/overview)、[Skills 规范](https://agentskills.io/specification) |

### 6.2 原理正确但学生训练不够完整的地方

**重试与缓存：** M09-T02 的原则要求预算、模型身份、提示版本和并发边界。教师主要示范缓存键和一次命中，`seat_cache_key` 只有问题、资料与 revision 三项，未包括模型身份；学生契约主要要求有限重试与次数记录。教学可以简化，但应明确是哪一层的示范，并补足跨模型身份与总 deadline 的可观察检查。不能让学生把小例子直接当作生产缓存方案。位置：[M09-T02](../../modules/09-runtime-and-service/02-runtime-policy.ipynb)，`teacher-mechanism`、`owned-contract`、`owned-real-policy`。

**语义裁判校准：** M06-T05 的核心实现 `audit_verdict` 审查 quote、字段与两份裁判结果的分歧。这个任务很有用，但单凭它不能证明学生已经掌握裁判校准或顺序偏差测量。应增加实际受控候选的顺序翻转、人工标注对照、重复结果与分歧统计；当前章末门禁的小数据也明确属于受控数据。位置：[M06-T05](../../modules/06-research-system/05-semantic-evaluation.ipynb)，`teacher-mechanism`、`owned-checks`。

**独立开发：** M10-T03 允许选择公告比较或偏好解释，要求保留旧行为并做回归，这是合理的渐进迁移。它仍是受限的毕业练习，而不是完全开放的需求分析。当前固定检查先核对保留状态和新增字段，功能效果还依赖后面的本人真实对照与迁移。不要把前一格通过当成新增能力已经有效。位置：[M10-T03](../../modules/10-opening-capstone/03-independent-feature.ipynb)，`owned-contract`、`owned-checks`、`owned-transfer`。

## 七 课程顺序与新手体验

### 7.1 宏观顺序合理

先理解消息与数据契约，再理解工具申请和反馈循环，再把循环放进图，是清楚的数据流递进。图之后学习检查点、审核和记忆，能避免一开始就把所有对象混在一起。单体研究先于多智能体协作、自己实现先于成熟 harness 对照，也有助于学生看清框架的责任。

M08 的源码维修放在已有本人组件之后，有真实维修对象。M09 在 M10 交付之前补运行政策，具有逻辑关系。无需为追热点而重排全部目录。

### 7.2 三处顺序值得调整

第一，在 M01 原位加入模型基础小节：token、上下文窗口、生成与采样、知识与当前输入、训练与推理、工具请求为何仍需程序执行。当前全 Notebook 检索中，`temperature` 等词主要出现在配置代码；未看到一套完整的生成机制教学。学生可以先会用 API，但“理解原理”的目标需要这座桥。

第二，评估应从前面逐步出现。M01 判断事实与格式，M02 检查调用与权限，M05 开始记录证据召回；M06 再统一质量、成本、延迟与实验方法。当前不是完全没有前置检查，缺的是将这些检查明确串成持续评估习惯。

第三，服务能力可以在代码维修之前设置阶段成果。希望用于工作或个人项目的学生，应在完成研究与协议组件后先交一项可使用的小服务；Coding Agent 可以继续作为同一项目的专修。现有目录不必立即改编号，但阶段验收应允许清楚表达已实现与待接线的能力。

### 7.3 入门友好的优点

M01-T02 从字符串排版、字典、类与对象、异常、序列化到真实结构化调用，给了不同的小例子、实际 prompt、模型返回和分层提示。它还明确告诉学生：定义异步函数不等于执行，类型注解不替代运行验证。对于初学者，这是很好的讲授方向。

故事中的障碍普遍能解释技术用途；每关有休息点；接口名称保持准确；错误保留而不伪装成功。统一接待台也使学生能把函数当成产品自由使用，而不仅盯住断言。

### 7.4 后半程的主要认知负担

**16 份 Notebook 使用同一套通用三层提示，且 `course-principles` 与 `deep-principles` 的正文重复。** 通用提示如“先对照函数签名，找出当次参数与应返回的字段”适合作为学习提醒，却不能替代具体语法与机制教学。名单见配套证据 JSON。

例如 M09-T02 的 `python-before-code` 列出 hashlib、JSON 规范化、异常、缓存和 Semaphore，随后是普遍的函数、字典、列表、集合和 await 说明。它没有在这一段完整解释 Semaphore 的取得/释放、异常分类与调用预算的状态变化。M10-T03 提到 kwargs，也没有在该段给出专门的小例子。前文有知识不意味着新手会自行拼出完整机制。

每章第一关的完整企业手册有深度，但信息量大。应让可选深入内容与本次马上要写的核心步骤更明确；每个小时对应一个可观察产物，而不是把长手册看完才开始编码。

**零前置知识不等于零环境门槛。** 当前入口仍需要 Git、uv、环境文件、模型账号与 Jupyter 内核，后面还需要 embedding 下载和 Docker。doctor 已存在，是优势；仍需要在当前页给出首次准备、常见失败和完成信号，尤其是学生自行从干净环境开始的证据。

### 7.5 实际学习量

catalog 的核心任务 pacing 合计 **148 次约一小时**。路线另预留每章生产深入约 3–6 次，十章合计 **30–60 小时**；相加约 **178–208 小时**，这是教材估计，不是学习效果测量，也未完整计入额外排障、复习和求职项目。

按每周 5 小时计算，约 36–42 周；按每周 10 小时计算，约 18–21 周。零基础可能需要更久。原有“每次约一小时”应解释为一次学习会话，而不是“一小时学会一个复杂任务”。

## 八 需要优先处理的具体问题

优先级含义：P1 为影响学习连续性或关键能力证明的问题；P2 为影响目标覆盖和教学质量的问题；P3 为维护与表达问题。这是课程审查的优先级，不是线上事故等级。

### F01 P1 M01-T02 导出前置依赖与本人契约不一致

教材要求 `answer_for_board` 使用 `structured_model` 与 `STORY_PROMPT`。导出格的前置代码只创建 `model` 与 `SYSTEM_PROMPT`，没有创建前述两个名字。导出器只调用 `compile` 检查语法，不检查函数运行依赖。因此，按当前契约编写的函数有可能在 Notebook 内正常，在导出的 project 模块调用时出现 `NameError`。

本轮临时诊断复现了“未定义全局变量可通过导出，调用时失败”；它未执行当前尚未完成的 `answer_for_board`。**具体教材不一致已确认，未来学生实现的实际失败仍取决于其代码。**

位置：[M01-T02](../../modules/01-langchain-foundations/02-notice-board.ipynb)，`learner-function-contract` 与 `additional-owned-export`；[learner_exports.py](../../instructor/learner_exports.py#L108)。

建议：统一运行依赖名字和模型副本配置，明确导出的教师设施；用无答案的设施诊断检查依赖闭包，再对真实本人导出做新进程验收。验收应覆盖导入、一次正常调用、空输入、schema 与事实边界，并保持原配置。

### F02 P1 导出迭代缺少可操作的安全更新流程

M02-T02 告诉学生修改后保存并重新导出；当前导出器在目标文件内容变化时一律拒绝覆盖。保留学生修改的规则是正确的，但学生需要知道怎样区分上次导出、本次 Notebook 修订和 project 自己的改动。

位置：[M02-T02](../../modules/02-tools-and-agents/02-tool-dispatch.ipynb)，`export-explanation`；[learner_exports.py](../../instructor/learner_exports.py#L109)。

建议：提供按来源指纹比较、预览差异、备份和安全更新的流程；project 有独立改动时保留冲突。不要以自动覆盖或删除旧文件来消除报错。

### F03 P1 教师验证尚未覆盖学生跨关集成风险

44 份教师示范和 84 项测试真实有用，但大量学生格被跳过，当前也没有导出的本人项目。后续对本人实现的真实 RAG、研究、协作、语义评分、自由接待台和毕业流程仍待完成。F01 是这种覆盖边界产生实际风险的例子。

建议：在保留学生核心实现的前提下，对导入设施、参数接线、状态传递和缺依赖行为做独立测试；完成每章后再用实际本人作品验收。报告和课程主页继续分别列出教师材料状态与学生能力证据。

### F04 P2 16 关的具体教学支架不足且正文重复

已确认的重复段落与通用提示集中在扩展任务及 M09/M10。其原理文字并非空白，问题是学生从小示范到完整函数的距离仍偏大。

建议：每关增加 2–4 个可运行的小步，展示具体值、类型和状态变化；提示依次指向概念、数据与一个局部行为。去除重复段落，腾出的篇幅用于真实机制讲解，而不是减少独立编码。

### F05 P2 当前入口仍残留文字复盘要求

M01-T02 的 `pause-one` 要求“用一句话解释”，`debrief` 要求把空表填成自己的观察，与课程已经接受的“复盘和原理问答以选择题完成”不一致。

位置：[M01-T02](../../modules/01-langchain-foundations/02-notice-board.ipynb)。

建议：改成对应原理选择卡和可选观察表，保留本人关键代码、运行对照和迁移，不增加必填文字总结。

### F06 P2 模型基础与原生接口视角不足

当前能训练 API 数据流，但全面理解 Agent 还需要知道模型如何生成、为什么上下文有边界、采样与重复运行是什么关系、schema 与语义为何分离。

建议：M01 原位加入短实验；后续选修一次相同工具与验收下的原生 API 或另一运行时移植。主线仍保留 LangChain/LangGraph，避免多框架同时入门。

### F07 P2 中文检索与效果指标不足

英文小型 embedding、英文官方资料与受限索引可以证明基本机制，不能证明学生常见中文项目效果。当前已有 recall@k 等概念说明，但未形成完善的本人检索测量任务。

建议：采用一组有证据位置标注的中英文馆务查询，分别测关键词、向量和融合，记录 Recall@k、MRR 或 nDCG，并按无答案、版本变化、相似但无关问题拆开错误。模型选择先由任务结果决定，不自动换配置。

### F08 P2 评估与研发缺少充分的实际优化实验

单次消融、来源检查和裁判审计是必要起点；研发还需要合理基线、开发/验证/留出边界、重复运行、人工校准、成本与延迟，以及失败类别。

建议：完成一个完整的失败驱动改进循环，并报告改进在哪类输入有效。给随机波动留下不确定性，避免以一次好结果宣称策略优越。

### F09 P2 就业与真实业务迁移路径不完整

没有清楚组织“哪些实现证明哪项岗位能力”，也没有独立作品集门禁。M10 的限定功能练习不足以代表完整的需求分析能力。

建议：增加业务流程选择题、现场需求修改、故障定位和作品整理模板；第二个项目仍可在雾岛世界中选择未排练的馆务需求。验收者只提供需求与结果契约，不提供分层实现路线。

### F10 P2 部分示范范围小于学生任务范围

M09-T02 的教师代码重点是缓存，而本人题还要求重试与预算；M06-T05 的核心题重点是裁判回执审计，而章节名称还包含偏差和校准。每关的真实公告调用已经正确标为输入边界验证，它不能补足其他机制的教学覆盖。

建议：给不同场景的完整教师演示，再渐进接通学生的关键机制；每份验证记录增加“本次实际验证的机制”与“仍未验证的能力”。

### F11 P3 静态检查口径与 Notebook 维护需要统一

现有设施 Python 检查通过；Notebook 纳入同一配置时有 533 项诊断。主要是样式，少数涉及 zip 严格配对、异步阻塞和循环变量等。不要为了过检查重写学生实现，也不要将所有诊断混成逻辑故障。

建议：为教学分格建立合理的检查规则，先检查教师格和导出设施；记录忽略理由，再处理真正影响契约或运行的诊断。

### F12 P2 新手效果尚缺独立学习者证据

当前有一位学习者第一关的部分证据，不能据此推断全部课程对零基础学生有效。课程设计质量与教学效果需要分别观察。

建议：记录首次独立尝试、提示级别、错误类型、实际会话时间、跨关回归和陌生需求迁移；选择题、编码和迁移继续分开登记。AI 导师如果接管核心实现，应记录帮助范围，不能将结果算作独立完成。

## 十 面向学生的学习与毕业标准

### 10.1 建议采用四个阶段成果

**第一阶段 M01–M03：理解并亲手造一个最小 Agent。** 能构造实际消息、实现工具与回执、处理有限错误，并把反馈循环变成图。成果必须来自自己的函数，不只是运行教师 demo。

**第二阶段 M04–M06：做一个可靠的知识与研究助手。** 能恢复委托、管理记忆，取得真实原文、检索并组织证据，拆开结构成功与语义支持，保留失败和未解决问题。

**第三阶段 M07 与 M09：将系统变成可用产品。** 接协议与方法、理解成熟 harness，完成流式、预算、身份与服务入口；清楚描述当前能做什么和待接线什么。

**第四阶段 M08 与 M10：完成专修与独立交付。** Coding Agent 用自己的已有组件接受受限维修；毕业作品在新进程运行，面对新需求并通过旧能力回归。随后再根据求职或研发方向选择扩展。

这是阶段成果建议，不是本轮对 README 当前入口或模块编号的修改。学习者仍从 M01-T02 继续。

### 10.2 不能缺少的毕业证据

| 能力 | 应有的实际证据 |
|---|---|
| 理解 Agent | 选择题能分清 workflow、模型决策、工具执行与 harness；正确选项不替代编码 |
| 独立实现 | 在签名、契约和分层提示下写出关键机制，记录帮助范围 |
| 跨关保留 | 错误回执进入图，记忆与上下文进入研究，证据进入协作，评分进入交付 |
| 故障定位 | 能定位首次输入、状态、工具或版本偏差；修复后用实际回归证明 |
| 设计取舍 | 相同需求下判断最小方案，比较质量、成本、延迟与失败边界 |
| 迁移 | 完成同域新输入，再完成一个此前未排练的馆务需求，保留不成功的案例 |
| 可复现交付 | 代码、prompt、依赖、测试和实际结果绑定；新进程能启动、停止、恢复和处理正常输入 |
| 研发起点 | 一个可重复的基线与改进实验，能说明改进来源和不确定性 |

建议用这些证据判断是否达到学习目的，而不是以 Notebook 数量、框架数量或教师通过率作为毕业标准。

## 十一 审查边界与最终判断

本次没有发现重点抽查范围内把文本经验称为权重训练、把 checkpoint 称为通用恰好一次执行、把合法 JSON 称为事实正确等核心概念错误。实际发现了学生导出依赖不一致、迭代工作流缺口、部分通用教学支架和验证范围不足，以及就业与研发目标的覆盖缺口。

本次不包含所有隐藏作业、完整安全审计、所有提供方兼容性、全体新手学习实验或市场穷尽调查。检索覆盖判断结合了目录、全文关键词核查和重点精读；某项未看到完整实践，不等于所有相关文字都不存在。

没有修改课程源码、题库、目录、README、prompt、模型配置、学生 Notebook 或学习状态；没有代填答案、运行未完成本人路径、提交、推送或打完成标签。新文件仅用于保存报告、方法和审查证据。

**建议继续把它作为 Agent 应用工程主线。** 在修好最早的接线问题、完善后半程小步教学并取得真实学生迁移证据之后，它可以成为质量较高且有辨识度的中文课程。若目标同时包含工作落地、求职和研发，应补足业务迁移、职业成果与研究实验三个方向；现阶段宜称为有特色的课程项目，不宜称市场唯一或全面研发训练已经完成。
