当前课程已于2026-10-03扩展为10章44关。下面保留早期整改依据；当前材料、接待台设施和验证范围以[验收清单](ACCEPTANCE.md)、state.json与validation.json为准。十章统一工作台已经提供，本人业务绑定与学习完成单独核对。

本页给后续导师交接使用，学习入口仍为根 README 的当前 Notebook。日期：2026-09-13。

## 参考怎样转成教材

[Hello-Agents](https://github.com/datawhalechina/hello-agents) 的目录把经典机制构建、框架、记忆与上下文、协议、评估和综合应用相连。这里吸收“先解释机制，再实现并进入应用”的组织方式，保持本课程的 LangChain / LangGraph 主线。以下修改是针对本仓库代码与学习者反馈作出的设计判断，不声称参考课程已经验证了本课程的学习效果。

每章的剧情用馆里遇到的障碍引出技术；每项原理说明输入、处理、输出与限制，随后进入同一本 Notebook 的示范和本人代码。`course_enrichment.json` 是这些内容及题库的共同源；生成器只修改命名的受管理格。不得给不同 harness 另写一套相互矛盾的答案或学习入口。

## 教师验证与本人掌握分开

28本教材在新内核中只执行 `setup/demo`，真实模型、HTTP、MCP、本地embedding与Docker按各关实际路径验证。原有本人代码和已保存结果保留。逐关结果、执行与跳过格清单以 [validation.json](validation.json) 为准；不根据文件数量推断本人完成。

M01接待台另外复用了学习者已保存的 `answer_reader` 做真实浏览器接线验证：两份公告、取消、空输入、选择题反馈和窄屏布局。该次运行是教师验收，记录隔离在 `outputs/validation/interactive-check`，不写入本人进度。第二关的结构化函数和后续核心机制仍由本人完成。

## 下一个导师如何继续

当前任务仍为 M01-T02。先确认本人正在看的格子和实际尝试，再帮助一个具体数据流或语法问题。课末让本人选择判断卡、核对作品和换输入，不布置文字总结。每到模块末，按 [INTERACTION_DESIGN.md](INTERACTION_DESIGN.md) 绑定本人能力，至少验证正常、失败或取消、迁移三类交互，并更新 `state.json` 的界面交付状态。未接线的功能写清楚，不能显示假进度或成功动画。
